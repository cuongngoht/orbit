# Antigravity CLI setup

The supported integration is the native CLI plugin with protocol 2 hooks.

## Install as a plugin (every machine)

```sh
agy plugin install <plugin-root>
```

The plugin's root `hooks.json` is protocol v2 and names `node cli/learn-hook.mjs …` **relatively**:
AGY CLI 1.2.12 runs a plugin hook with its working directory set to the plugin's install
directory (measured, and what AGY's own hooks guide says), so the same file works on every machine and
carries no installation path. It is generated by `pluginHooks()` in
`skills/orbit-learn/hosts/setup.mjs`, and a test holds the file to it. AGY exposes no
plugin-root variable of its own (it does set `CLAUDE_PLUGIN_ROOT`, which Orbit does not rely on);
plugin hooks run without a separate trust step. The workspace comes from the payload's
`workspacePaths`, never the hook's working directory, so every checkout keeps its own project room.

## Or wire one workspace

A workspace-level entry cannot be relative to the plugin (its working directory is the workspace's
`.agents/`), so it carries the absolute installation root of THIS machine -- do not commit it:

```sh
node "$orbit_plugin_root/cli/host.mjs" inspect --host=antigravity --target=/absolute/workspace/.agents/hooks.json
node "$orbit_plugin_root/cli/host.mjs" render --host=antigravity --target=/absolute/workspace/.agents/hooks.json
```

Review the entry/revision, then explicitly `apply` with `--revision=<sha>`. Replacing an existing `orbit-learn` entry requires `--replace`. Setup keeps other entries and saves a backup/receipt. `remove` with a fresh revision restores the previous owned entry and leaves other hooks and the machine store intact. Concurrent edits refuse the write.

Setup detects an owned entry at its target. Confirm the integration in the native loaded inventory.

PreInvocation at invocation zero bootstraps context, not prompt routing. Stop is an execution boundary, not SessionEnd, and never asks AGY to continue for pending Orbit work. Use the [stdin routing workflow](hosts.md#root-and-session-binding). Native external MCP inventory is unknown because this target CLI publishes no JSON list contract; managed Orbit MCP remains available.

`agy plugin validate .` validates package structure only. Native acceptance must also verify permission responses, recall, multi-workspace containment, background outcomes, Stop, retry/rollback and operation without Control.

Sources: [hooks](https://antigravity.google/docs/hooks?tab=ide), [plugins](https://antigravity.google/docs/ide-plugins?app=antigravity-ide).
