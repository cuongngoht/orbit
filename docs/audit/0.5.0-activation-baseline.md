# Orbit 0.5.0 — Activation baseline (B22, milestone M0)

**Measured:** 2026-11-05, on `release/0.5.0` at `c803ce1` (plugin 0.4.0 code). No product code changed for this audit.
**Feeds:** [the design](../backlog/0.5.0-proactive-orchestration.md) §2 and §7, and
[ADR 0050](../adr/0050-the-host-activates-orbit-by-capability-and-orbit-verifies-what-happened.md).

M0 asks what is true before B22 changes anything: what the host lists, which native mechanisms behave as the design
assumes, and whether the benchmark's real host answers here. Everything below names its source: a captured payload, a
documentation page, a run on this machine, or an observation in the session that drafted the design. Anything still
open is said to be open.

## 1. What the host lists

| Metadata | Count | Characters |
|---|---|---|
| Skill descriptions (`skills/*/SKILL.md`) | 25 | 17,924 |
| Agent descriptions (`agents/*.md`) | 20 | 12,180 |

- **Budget.** Claude Code budgets the skills listing at 1 % of the context window, at most 1,536 characters per entry,
  and drops the descriptions of the least-used skills first when the listing overflows
  (https://code.claude.com/docs/en/skills.md).
- **Overflow observed.** In the session that drafted the design, the host's listing showed `orbit:satellite` with no
  description, beside four other plugins' skills in the same state. The listing was already over budget there.
- **Agent descriptions are listed whole** in the Agent tool's own description, so their 12,180 characters are in every
  session's context.
- **`/skill-doctor` was not run.** It is an interactive command. The activation suite's arms measure the same thing on
  every release, with the real host.

## 2. Native mechanisms, as the design relies on them

| Question | Answer | Source | What it means for the design |
|---|---|---|---|
| What does an Agent call carry? | `tool_input.subagent_type = "orbit:<agent>"`, and `prompt` | Captured: `test/fixtures/hooks/claude/PreToolUse-Agent-2.1.309.json` | The judge and the trail can name the agent dispatched |
| What does a subagent's end carry? | `agent_type`, `agent_id`, `stop_hook_active`, `agent_transcript_path` | Captured: `SubagentStop-2.1.314.json` | The trail names the agent; its last message is never read (ADR 0044) |
| What does Stop carry? | `stop_hook_active`, `last_assistant_message` | Captured: `Stop-2.1.309.json` | The hold can guard on `stop_hook_active` |
| What does a Skill call carry? | `tool_input.skill = "orbit:<skill>"` | Orbit's switch refusal reads it, and `test/plugin-options.test.mjs` feeds it. **No captured native payload** yet. | Capture one with the activation suite's first real run |
| Does Stop fire when a person interrupts? | No | Docs, hooks page, "Stop" | A hold can never override a person's interrupt |
| After a Stop block, is the next Stop `stop_hook_active: true`? | Yes. After eight consecutive continuations the host ends the turn anyway (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`). | Docs, hooks page, "Stop" | The hold's own bound (at most 2 per prompt, never when active) stays well inside the host's |
| Does Stop fire under `claude -p`? | Likely: hooks run in `-p` unless `--bare`. Not stated for Stop explicitly. | Docs, headless page | Confirmed by the activation suite's runs, which use `-p` |
| Does PostToolUse `additionalContext` reach the model? | Yes, beside the tool result. An `async` hook's context arrives on the next turn instead. | Docs, hooks page | The agent-return line needs a **synchronous** PostToolUse entry matched to `Agent` |
| Does PostToolUse fire after an Agent call returns? | Not documented for Agent specifically | — | Open: confirm in the activation suite's first real run before M3 relies on it |
| Can an agent's `tools:` narrow Bash to a pattern? | **No.** `tools` and `disallowedTools` take tool names; a specifier in `disallowedTools` removes the whole tool. | Docs, sub-agents page | Open question 12 is answered: frontmatter cannot narrow the seven read-only-by-contract agents. A synchronous PreToolUse rule could, at the cost of a hook on every Bash call; deferred. |
| Does a deny rule `Skill(orbit:x)` remove the skill from the listing? | Not documented | Docs, skills page | Open. `disable-model-invocation` is the documented way to remove a skill from context; the design keeps every skill model-invocable. |
| Are host notifications delivered to UserPromptSubmit? | Yes | Observed: in the drafting session, three background-task notifications each received the router's context, routed `investigation (high confidence)` | The router must answer nothing for a host envelope (B22 M2) |
