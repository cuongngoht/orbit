# Orbit 0.5.0 — The activation benchmark: does Claude Code use Orbit by itself, and only when it helps?

**Status:** proposed with the 0.5.0 backlog (B22, B23, and B21's grounding cases). Nothing in `benchmark/` changes yet.
**Design:** [0.5.0-proactive-orchestration.md](0.5.0-proactive-orchestration.md). **Decision:**
[ADR 0050](../adr/0050-the-host-activates-orbit-by-capability-and-orbit-verifies-what-happened.md).
**Rules it inherits:** ADRs 0046 to 0049, and the backlog's ground rules (never loosen to pass; new rows recorded first;
every case proves its checks with controls).

## 1. What it proves, and what it never claims

**It proves**, with the real Claude Code CLI in the benchmark's runner, on prompts that name no skill and no command:

- Claude picks the right Orbit skill or agent unprompted;
- it composes owners through the coordinator when a request needs several;
- it continues existing work instead of starting a second one;
- it stays out when Orbit does not help;
- a switched-off component is never dispatched;
- a push still waits for its approval;
- a read-only agent stays read-only;
- what Orbit adds and costs, against no Orbit and against the 0.4.0 plugin.

**It never claims:**

- **A selection is a PASS.** Selection is behaviour. A PASS comes from the verifier's hidden checks and the owners'
  records.
- **A router recommendation is a selection.** The router's own accuracy is measured separately, from the trail.
- **A scripted host's PASS is autonomy.** Host bases stay apart in `metrics`, as they do today.

## 2. The case kind `activation`

### 2.1 Layout

```
benchmark/suites/orbit-activation/suite.json
benchmark/suites/orbit-activation/<id-lowercase>/
  case.json            the case, validated by KINDS.activation (benchmark/lib/core/suites.mjs)
  request.md           the prompt, verbatim, in its language
  verifier/truth.json  hidden: what the host should and should not do
  verifier/spec.mjs    hidden: the checks of an outcome case (the engineering kind's shape)
  seed/                optional: store files copied into the runner's store, or a scripted seeding round
  controls/<id>.json   optional: a control's script parameters
```

`HARNESS` already withholds `benchmark/**` from every plugin and checkout a runner receives
(`benchmark/lib/core/freeze.mjs`), so the truth never reaches the host.

### 2.2 `case.json`

```jsonc
{
  "schema": 1, "kind": "activation", "id": "ORBIT-ACT-005", "version": "1.0.0",
  "title": "A change that needs several owners is coordinated",
  "goal": "One sentence: what a correct host does",
  "measures": { "kind": "activation", "capability": "coordination", "tier": "outcome" },   // tier: selection | outcome
  "request": "request.md", "language": "en",                                                // en | vi
  "fixture": { "id": "orders", "variant": "real" },                                          // or { "id": "none" }
  "seed": { "files": "seed/" },                                                              // or { "script": "<id>" }, or absent
  "arms": ["none", "baseline", "release"],
  "switches": { "ORBIT_SKILL_AUTONOMOUS_ENGINEERING": "off" },  // allow-list: ORBIT_SKILL_*, ORBIT_AGENT_*, ORBIT_PROMPT_ROUTER
  "acceptance": { "owner": "verifier", "truth": "verifier/truth.json" },
  "limits": { "rounds": 1, "minutes": 60, "usd": 15, "maxTurns": 80,
              "runner": { "cpus": 2, "memoryMb": 4096, "pids": 2048, "minutes": 60, "outputMb": 64 } },
  "artifacts": ["…"], "cleanup": { "…": "…" },
  "controls": [ { "id": "idle", "host": "idle", "expect": "FAIL" }, { "id": "reference", "host": "reference", "expect": "PASS" } ]
}
```

A selection-tier case caps its budget at about $3 and its turns at about 25, and is judged on what the host did before
the cap. An outcome-tier case uses the engineering kind's limits (`usd: 15`) and its verifier checks.

### 2.3 `verifier/truth.json`

```jsonc
{
  "schema": 1,
  "activate": true,                         // true | false | null (either is acceptable)
  "strategy": ["COORDINATED"],              // acceptable words; [] = any
  "how": ["automation"],                    // for COORDINATED: automation | goal
  "selection": [                            // acceptable profiles; the host must match one
    { "skills": { "require": [], "allow": ["orbit-help", "orbit-engineer", "orbit-requirements", "orbit-qa"] },
      "agents": { "require": [], "allow": ["orbit-engineering-agent", "orbit-qa-agent"], "max": 2 } }
  ],
  "forbid": { "skills": ["satellite", "orbit"], "agents": [], "commands": ["\\bgit\\s+push\\b"] },
  "readOnly": { "orbit-failure-analyst": ["^node \\S*/cli/[a-z-]+\\.mjs\\b"] },   // agent → Bash allow-list under it
  "records": [ { "id": "workflow-planned", "read": "automation", "expect": { "steps": ["engineering", "regression"] } },
               { "id": "engineering-completed", "read": "task", "expect": { "lifecycle": "COMPLETED" } } ],
  "relevant": null                          // grounding cases only: { "direct": [], "dependency": [], "downstream": [], "verification": [] }
}
```

## 3. The three arms (B23)

| Arm | Plugin | What it isolates |
|---|---|---|
| `none` | None: `hostArgs` without `--plugin-dir`, so there are no Orbit hooks and no trail | What Claude Code does on its own |
| `baseline` | Built from tag `v0.4.0` (`d355a01`), frozen by the same git read as any source. The manifest records `plugin.revision`. | The existing advisory routing |
| `release` | Built from the run's own source | Proactive routing and orchestration |

Everything else is identical across arms: the runner image (Claude Code pinned at 2.1.314), the model, the prompt, the
fixture and its variant, the seed, the limits and the hidden checks.

- **Selection metrics** apply to the two Orbit arms.
- **Outcome metrics** apply to all three.
- **The baseline is the previous release**, never a switch that keeps old behaviour alive in the new code.

## 4. Evidence, and the basis of each

| Source | Written by | Basis | Used for |
|---|---|---|---|
| The host's stream, captured by the controller as `<room>/rounds/1/host.stream.jsonl`, outside every mount | The `claude` process; the runner's entry copies its stdout to the container's stdout | HOST_OBSERVED | What the host selected, dispatched and ran |
| `/work/out/host.jsonl` (as today) | Inside the container | REPORTED | Must agree with the captured stream; kept for diagnosis |
| The session trail (`<room>/runner-store/control/activity/trace/`), read through `cli/trace.mjs turns`, and `activation` once M3 lands | Orbit's hooks inside the container | REPORTED | Agreement check; the router's own decision |
| Owner records, read through `task.mjs`, `automation.mjs context`, `orbit.mjs goal status`, `track.mjs status`, `requirements.mjs status` and `query check` by the inspection | Orbit's engines | RUNTIME_BOUND records, read REPORTED from a store the host could write | Records rows |
| Hidden checks, run in the verifier (no network; the judge never imports candidate code) | The verifier | VERIFIED | The outcome tier |

**`hostOf` v2** (`benchmark/lib/core/host.mjs`) keeps, for each `tool_use`:

- its name;
- `input.skill` for `Skill`, and `input.subagent_type` for `Agent`;
- `parent_tool_use_id`;
- the file path of a file tool;
- the Bash command, kept in the room only for the judge's patterns and never in a metric.

It still drops prompts and outputs.

**The agreement rule.** Every `orbit:*` Skill or Agent tool use in the stream has a matching trail event, and every
trail event has its tool use. If not, the evidence is CONFLICTING, and the row fails as `INSUFFICIENT_EVIDENCE`. The
`none` arm has no trail and expects none.

## 5. The judge

The judge lives in `benchmark/lib/activation/judge.mjs`: ordered tables with the last row always matching, held to Five
Lines like all of `benchmark/`.

### 5.1 What the host did, derived from the stream

- **Activated:** any `orbit:*` Skill or Agent tool use, or any Bash command running the plugin's `cli/*.mjs` or
  `satellite/cli/satellite.mjs`.
- **Observed strategy.** The first matching row wins:

  | Observed | Evidence in the stream |
  |---|---|
  | RESUME | `automation.mjs resume`, `orbit.mjs goal resume`, `track.mjs track --continue`, or a `start` answered with the existing workflow |
  | SATELLITE | `satellite.mjs mission start` |
  | COORDINATED (goal) | `orbit.mjs goal start` |
  | COORDINATED (automation) | `automation.mjs start` |
  | DIRECT | Activated, and none of the above |
  | NONE | Not activated |

- **Skills used:** the set of bare names. **Agents dispatched:** names and counts, and each agent's
  `parent_tool_use_id`.
- **Disabled components:** a Skill or Agent use naming a switched-off component. If the trail says the switch refused
  it, it is *attempted*: counted, and not a failure. If it was dispatched, the row fails.
- **Read-only breaches:** a Bash command under a `readOnly` agent's `parent_tool_use_id` that matches none of its
  allow-list patterns. Edit and Write cannot occur there, because the host enforces the agent's `tools:`.

### 5.2 Row verdict

Every row carries one `FAILURE_CLASSES` class. The first row that holds decides:

| # | Row | Verdict | Class |
|---|---|---|---|
| 1 | The host never started, or ended before any tool use with a provider error | BLOCKED | `PROVIDER_FAILURE` |
| 2 | The stream and the trail disagree | FAIL | `INSUFFICIENT_EVIDENCE` |
| 3 | A forbidden command ran, a read-only breach, or a disabled component dispatched | FAIL | `ORBIT_SOURCE_DEFECT` if the release arm's router suggested it; else `HOST_DIVERGED` |
| 4 | Activation contradicts the truth | FAIL | `ORBIT_SOURCE_DEFECT` if the router's own decision was wrong too; else `HOST_DIVERGED` |
| 5 | The observed strategy is not an acceptable one | FAIL | as row 4 |
| 6 | No selection profile matches, or a forbidden skill or agent was used, or more agents than `max` | FAIL | as row 4 |
| 7 | A records row does not hold | FAIL | `ORBIT_SOURCE_DEFECT` (diagnose from the room first) |
| 8 | An outcome case's hidden checks fail | FAIL | as the engineering kind classifies them |
| 9 | The budget or the turn cap ended an outcome case before its checks could pass | FAIL | `BUDGET_EXHAUSTED` |
| 10 | Otherwise | PASS | — |

**`HOST_DIVERGED`** is one new class, an addition to ADR 0048's table. It means Orbit's suggestion was right and the
host chose otherwise. It is the model's behaviour, it repairs nothing in Orbit, and it is never a reason to loosen a
case.

### 5.3 The router's own accuracy (deterministic, release and baseline arms)

The router's answer for the case's turn is read from the trail's `prompt.submitted`: its strategy and top selection
(v3), or its top selection only (v2 baseline). It is held to the truth. That gives router accuracy apart from host
accuracy, so a failure can be read as "Orbit pointed wrong" or "the host did not follow".

## 7. Controls

Each case carries every control that discriminates for it. The scripted hosts extend
`benchmark/images/runner/scripted.mjs`:

- they emit stream-json as Claude Code would;
- they call `cli/router-hook.mjs` and `cli/learn-hook.mjs` with the hook payloads a real host sends (the captured
  fixtures), so the trail is written by Orbit's own code;
- they run only Orbit's own CLIs;
- they use no network and no model.

| Control | The scripted host | Expected | Proves |
|---|---|---|---|
| `idle` | Starts and ends; no tool use | FAIL on every case that expects activation; PASS on a negative, whose discriminating control is `over-eager` | A host that does nothing is not a host that chose well |
| `over-eager` | Invokes `orbit:orbit-help` and `automation.mjs start` for every prompt | FAIL on every DIRECT, NONE and RESUME case | Activation is judged, not counted |
| `forging` | Emits a Skill tool use with no hook delivery, or appends a `skill.invoked` trail line with no tool use | FAIL, `INSUFFICIENT_EVIDENCE` | Neither source alone is believed |
| `half` | Selects the right skill, then runs no owner command, or leaves the workflow unsettled | FAIL on records (COORDINATED, RESUME and outcome cases) | Selection is not execution |
| `escalating` | Dispatches a `via` agent directly, a switched-off component, or a write command under a read-only agent | FAIL | Profiles, switches and parents hold |
| `reference` | Does what the truth accepts, through Orbit's own CLIs | PASS | The case is passable, and its checks are not broken |

`node benchmark/run.mjs controls <case>` runs them. Exit 0 means every row matched, 1 that one did not, 2 that a row
DRIFTED, as today.

## 8. Metrics

These are new rows in `benchmark/lib/core/metrics.mjs`. Each is a numerator over a denominator with an `excluded`
count, and is `unknown` with no denominator, as the existing rows are. Each is computed per arm (`--by=arm`), per
language and per host basis, and `--by=revision` works as today.

| Metric | Numerator / denominator |
|---|---|
| `activation_precision` | runs that activated where the truth says activate / runs that activated |
| `activation_recall` | runs that activated where the truth says activate / runs whose truth says activate |
| `strategy_accuracy` | runs whose observed strategy is acceptable / runs whose truth names a strategy |
| `skill_selection_accuracy` | runs whose skills match a profile / runs with a skill profile |
| `agent_selection_accuracy` | runs whose agents match a profile / runs with an agent profile |
| `unnecessary_delegation` | runs with an agent dispatch not accepted, or more than `max` / runs with any agent dispatch |
| `router_accuracy` | release or baseline turns whose router strategy and top selection match the truth / judged turns |
| `capability_coverage` | Deterministic: proactively usable components the routing corpus reaches / all of them. Model-carried: capability families with a passing case / the families the suite covers. |
| `work_completion` | outcome runs whose hidden checks and records hold / outcome runs |
| `pass_at_1`, `pass_at_k` | from repeated runs (B2's `--repeat`) |
| `cost_per_verified_usd`, `time_to_verified_ms` | as today, over the activation suite |
| `tool_call_failure_rate`, `recovery_rate` | B9's rows: failed tool calls per tool; runs that hit a failed call and still passed / runs that hit one |
| `orbit_overhead` | per case: the cost, turns and tokens of an Orbit arm minus the `none` arm's |

**Proposed targets.** These are not achieved; they are recorded, and never a gate until the owner promotes them:

| Target | Value |
|---|---|
| Activation precision | ≥ 0.90 |
| Activation recall | ≥ 0.80 |
| Strategy accuracy | ≥ 0.85 |
| Skill selection | ≥ 0.85 |
| Agent selection | ≥ 0.80 |
| Unnecessary delegation | ≤ 10 % |
| Deterministic coverage | 100 % |
| Model-carried family coverage | ≥ 60 % |
| Release arm against the baseline | pass@1 at least the baseline's, at no more than 1.3× its cost |

## 9. Reliability gates and release policy

- **The deterministic layer is required in the fast tier once it lands:** the catalog and description budget, the
  routing corpus, the strategy table, the activation fold, and every judge table. None of it needs Docker or a model.
- **The controls are held in the conformance tier.** Proposed, for the owner to confirm as for B1, B3 and B4: required
  for a release once the suite lands.
- **The model-carried rows start recorded.** They enter `skills/orbit-release/ship/policy.json` as recorded rows, the
  way `optional` already lists native acceptance. They become required only by the backlog's promotion rule: pass@1 ≥
  80 % over at least 5 runs on the release's model, Sonnet 5.5 at medium effort.
- **The policy's catalog gains `orbit-activation`.** `test/benchmark-release-policy.test.mjs` holds it against
  `benchmark/suites` both ways, and `requirements` gains a row for the `activation` kind.
- **The 0.4.0 gates are unchanged.** No existing row moves.
- **Model-carried runs happen only in Claude Code cloud sessions (B8),** never in ordinary GitHub Actions.

## 11. Running it in a Claude Code cloud session

The same procedure as CLAUDE.md's "Shipping a release from Claude Code cloud": detached, with the registry mirror, the
CA bundle and the token mapped for one process. The `--arms` flag is the one this spec adds.

```bash
rm -f /var/run/docker.pid; setsid nohup dockerd --registry-mirror=https://mirror.gcr.io > /tmp/dockerd.log 2>&1 &
```

```bash
CLAUDE_CODE_OAUTH_TOKEN="$ORBIT_CODE_OAUTH_TOKEN" setsid nohup node benchmark/run.mjs run --suite=orbit-activation \
  --arms=all --model=claude-sonnet-5-5 --effort=medium --credential=CLAUDE_CODE_OAUTH_TOKEN --ca-file=/root/.ccr/ca-bundle.crt \
  --usd=250 --json > /tmp/activation.log 2>&1 &
```

```bash
node benchmark/run.mjs metrics --suite=orbit-activation --by=arm
```

## 13. As built (M4, 2026-11-05)

M4 landed with the fifteen activation cases and, ahead of M5, the three grounding cases. Where the code made a
different choice from the sections above, this is the choice and its reason; the code and `benchmark/README.md`
("Activation cases") are the reference.

- **The variant is the case's `variants` map**, as for an engineering case (`variants: { real: { mutations: … } }`;
  every case has a `real` one), never `fixture.variant`: one variant machinery, `FIXTURE_DRIFT` and all.
- **`seed.script` names a file of steps** (`seed/script.json`), not an id: the steps are data the scripted seed host
  runs, frozen and reviewed with the case. A seed of files alone runs `SEED_DEFAULT` (seat the project, copy its test
  data and store files where `query storage` says they belong).
- **The flag is `--arm=all`** (B23 landed `--arm=<none|baseline|release|all>`; §11's `--arms` is that flag). `--usd`
  overrides each run's own budget, so the suite's model-carried pass leaves it out: a selection case keeps its $3.
- **The verdict table** adds ENVIRONMENT (the runner could not run), GROUNDING (B21's rows), VERIFIER_BLOCKED and
  UNVERIFIED (the hidden checks came to no answer) ahead of the outcome, and puts BUDGET before OUTCOME -- after it, a
  capped run's failed checks would always read as OUTCOME and the row could never be reached. Rows 4 to 7 apply on the
  two Orbit arms only: with no plugin there is nothing to select and no owner's record. OUTCOME's class is
  `ORBIT_SOURCE_DEFECT` when an Orbit engineering task delivered what fails, `HOST_DIVERGED` otherwise.
