owner chose not to use the session's own token, so no native CLI run counts), or a CLI not installed. NOT RUN:
implemented, not exercised by a test or a run. UNSUPPORTED: not implemented in 0.8.0. NOT APPLICABLE: ruled out by the
owner's decisions.

## Disclosures

- Early in this work a canary of the real Claude Code CLI (an empty config home, meant to show which tools its first line
  reports) reached the model API once, through the session environment's own network authentication. It was not meant to,
  it is not evidence for any row above, and the real CLI was not run again.
- No native CLI row is PASS: the owner decided the session's own token is not used, and no other account was available.

## Limits that remain

- Temporary assistants (TTL, quota on the manager) are not implemented.
- No external delivery channel and no email verification channel: an external recipient waits for a channel; a share
  names a user by username (or by an email nobody can verify yet).
- Codex and Antigravity are adapters tested on fixtures; neither CLI is in the image.
- The team room's history is attributed per attempt (the files an attempt changed), not per write.
- Model-plane connections are limited to the providers' hosts but not logged per run; tool-plane connections are.
- In the governed deployment the one agent container mounts every account's AI connection homes, as it mounts every
  workspace (README, "The limit, said plainly").
- The workstation image is the Node base image (about 2 GB); the `process` provider is development only.
