# Orbit Web 0.8.1 -- acceptance and engineering report

Branch `Release-0.8.1`, from `main` at `127397bf` with the owner's `fc09be1f` on top; the 0.8.1 work is the commits
from `74195f31` (the proof of concept) to the release head. What was run, where, and what each result rests on. A cell
says only what was checked; what was not is said as such. The release candidate is **0.8.1-beta1**, pushed as pull
request #24 to `main` ([its own evidence](#081-beta1-the-release-candidate)); nothing is merged, tagged or published.

**Words used.** IMPLEMENTED AND VERIFIED: built, and a test or a run here fails without it. IMPLEMENTED BUT NOT
VERIFIED: built, and no test or run here exercised it end to end. PARTIALLY IMPLEMENTED: part of what was asked is
built. UNSUPPORTED: this kernel or sensor cannot do it, said by a probe. BLOCKED: needs a host or an account this
session did not have. NOT IN SCOPE: ruled out for 0.8.1 by a recorded decision (ADR 0063).

**The one host everything ran on.** Docker Desktop 29.9.3 on macOS, kernel 7.0.14-linuxkit aarch64 (10 CPU), BPF LSM
active (`capability,bpf,landlock`), `CONFIG_BPF_KPROBE_OVERRIDE=y`, BTF. No native Linux host, no x86_64 host, no cloud
VM and no rootless Docker was available to the tiers. For 0.8.1-beta1 a second host ran the deployment and its own probe
(never the tiers): a native Linux cloud VM, [below](#081-beta1-the-release-candidate).

## Readiness

**Not production-ready by evidence, and not claimed to be.** The independent review found a defect that every tier
missed, because no tier ran the API's rules on real kernel events: it would have stopped every enforced attempt. It is
fixed, and the rules now run on the real sensor's lines in a test, but one live enforced attempt -- a real sensor, the
allocator, the API's ingestion and rules, and an AI CLI working through its runner -- has still not run end to end
anywhere (the runner is unreachable from macOS, and no AI account was used). What 0.8.1 proves, it proves on one host: Docker Desktop
on macOS (kernel 7.0.14-linuxkit, arm64). There, observation, scoped prevention from shared areas, the gate before
untrusted code, and containment on policy drift, sensor restart and sensor loss all held, in the proof of concept and
in the real-kernel tier. The tiers ran on no native Linux host, x86_64, cloud VM or rootless Docker; for 0.8.1-beta1,
the deployment on a native Linux arm64 cloud VM proved by the host's own probe that observation, scoped prevention and
fileless detection hold there too -- no employee attempt ran under it.
Those are the hosts a production deployment would use, and the probe will say on each what it proves.

**What a person can rely on now:**
- runtime security off is 0.8.0's behaviour;
- observe records what an employee's programs do and says detections as detections;
- enforce on a host whose probe shows `prevent.exec` SUPPORTED refuses execution from shared areas for that attempt
  only, and holds an attempt whose proof is lost.

The recommended path for a new host is observe first; read the page's host card and incidents; then enforce for a
department.

**What stays open:**
- the window of about 20 s after the sensor dies in which the kernel enforces nothing (the gate, the egress refusal
  and the incident response narrow it);
- prevention is path-based and covers execution only;
- network and file observation in the kernel are not built;
- sessions and the governed agent are not enforced;
- the allocator-restart path is implemented but not exercised by a test;
- every native AI CLI path is BLOCKED here for want of an account, as in 0.8.0.

## Deferred findings of the review (minor)

Each was judged minor by its effect and left for a later change. Each is listed here, so nothing set aside is silent.

1. The watchdog acts on a snapshot: an action for a record released meanwhile can bring it back from CLEANED_UP.
2. An attempt that is only stopped (contained, or stopped by the allocator), not removed, keeps its policy on a
   namespace another container may reuse (threat model S5).
3. With the backend on and a floor of `disabled`, attempts whose mode is disabled are still registered and observed.
4. `openAttempt` does not compare the planes' start times with the ones proven; the next watch catches a restart.
5. Truth on the page:
   - the host card uses the last pulled sensor state without a staleness check;
   - a "lost" incident stays CONTAINING after the proof is renewed;
   - a prevented operation's incident says CONTAINED while the attempt runs;
   - stopped planes are renewed as PROTECTED until they are removed.
6. The host view shows deployment-wide counters (last event, lost, unattributed) and the kernel and sensor details to
   every account's owner.
7. Not in ADR 0063:
   - floor-raise reconciliation of running attempts;
   - a package-manager lifecycle rule;
   - per-account drop counters;
   - rebuilding records from labels (only enforced attempts with no record are contained).
8. The export reader can split a UTF-8 character across two reads and does not detect a file truncated in place;
   `restoreOpened` is unused.

Fixed with C1, from the same root cause: the host's fileless proof could be satisfied by runc's own memory-file exec.
